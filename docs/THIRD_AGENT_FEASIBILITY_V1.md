## Unchanged legacy protocol

Use existing legacy `class_index`, `abstain`, `evidence` only. Evidence is an
array of target-paper quotations; source is implicit target.text. Class indices
are canonical0..6. Abstention requires null class and empty evidence. Existing
parser/L1 rejects contradictions, fabricated/trivial quotes and malformed schema.
No silent rich-schema substitution, prompt revision, cohort replacement or retry.

Legacy observes a proposed class/abstention and quotations. It has no explicit
primary_topic, quote-to-claim explanation, counter-evidence, auxiliary-method
warning, uncertainty rationale or semantic-confidence field. Do not infer those
fields from its output. Rich v1 could collect them as diagnostics but would require
new approved prompts/schema/seals and output-budget review; it is excluded here.

For each node, sequentially in the fixed cohort order:

1. Reserve one sealed blind request. Supply target, authorized neighborhood and
   Atlas only: no B1/Narrative class, vote, confidence, GT or prior judge output.
2. Persist intent/binding before dispatch. Persist the immutable raw response,
   actual request/context hashes and usage before proceeding; parse and run L1.
3. Stop that node on abstention, invalid output, truncation, failure or uncertainty.
   Audit failures/unknown execution stop the pilot for reconciliation. Never retry
   or replace a failed node automatically.
4. Only valid non-abstaining blind permits one comparison. Bind its actual blind
   class into the existing template; preserve the raw blind hash and final payload
   hash. Comparison may see original candidate classes, as already authorized.
5. Parse/L1/audit comparison; preserve every result, including abstention and
   third-class proposals. No semantic label promotion or downstream training.

At most12 generations,16384 declared input tokens/call,512 output tokens/call,
timeout120 seconds and zero automatic retries. Input reservations are not measured
provider tokens. Do not enlarge output caps after inspecting failures. Conditional
comparison means equal node budget does not imply equal actual calls or cost.

## Minimum review of genuine outputs

Obtain two separately completed human assessments for each actually obtained
L1-passing non-abstaining response: up to12 phase responses /24 human records.
Record abstentions/malformed/unavailable outputs as feasibility outcomes, not
invented semantic assessments. Blind-stage support is the primary human-review
unit; evaluate comparison-stage outputs separately before linking phases.

Show complete admitted target text, public class definitions, the genuine proposed
class and exact quotations. If needed, explicitly label the review question as
the coordinator's proposition "the primary topic belongs to proposed class X";
this is not a model-generated explanation. Do not manufacture rich fields.
Use the existing four rubric questions/outcome vocabulary. Missing model reasoning
must remain missing: reviewers may identify unresolved counter-evidence, but cannot
credit an explanation absent from the response. Use NOT_ASSESSED with a reason
when the available output does not permit that dimension to be assessed.

Blind reviewers to GT, B1/Narrative votes/confidence, router strata, phase pairing,
author expectations and each other's answers. Randomize opaque review-case order;
record recognitions/prior exposure truthfully. No LLM assistance. Keep individual
records before any later consensus; preserve disagreements without auto-adjudication.
Validation checks self-attestations, not genuine identity or independence.

The prior six consensus development responses are instruction feedback only.
Do not reuse them as independent validation or a confirmatory holdout. Their
lessons inform a proposed clarification sheet: align each rationale with its
question, distinguish topic/application/method and quotation/support, explain
counter-evidence and missing input, and give accurate UTC/enum guidance. Do not
edit the existing rubric, packets, declarations or answers. New genuine-output
packets require a reviewed minimal adapter: current preparation is pinned to the
six illustrative development cases and cannot be presented as generic ingestion.

## Observable report, with denominators

Record requested, dispatched, completed, rejected, uncertain and not-attempted
counts separately by phase. Report JSON-valid/dispatched, L1-pass/dispatched and
L1-pass/JSON-valid counts; also raw numerators. Never count missing responses as
passes. Report rejection reason codes, truncation, abstentions/valid responses,
quote availability, audit-readback completeness and recovery incidents. Report
human usable-evidence observations separately from L1 quote validity; no Cora GT
accuracy, reviewer accuracy, improvement percentage or population inference.
Record provider-reported input/output/reasoning/cached usage when supplied,
actual charges when verifiable, and unavailable fields as unknown. Separate local
estimates/reservations from usage and invoiced cost. No guaranteed dollar cap.
